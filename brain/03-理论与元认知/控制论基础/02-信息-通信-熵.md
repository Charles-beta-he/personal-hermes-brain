# 02 - 信息、通信与熵

## 核心概念

控制依赖信息。没有观测，控制器无法判断系统偏离目标多少；没有通信，反馈无法传回控制器；有噪声，控制器会基于错误状态行动。

Shannon 信息论给出通信系统的抽象：

```text
信息源 → 编码器 → 信道 + 噪声 → 解码器 → 接收者
```

控制论把这个抽象接到行动闭环：信息不是为了“知道”，而是为了“调节”。

## 熵与不确定性

熵可以理解为系统状态不确定性的度量。对于 Agent：

- context 混乱越大，状态熵越高。
- evidence 缺失越多，判断熵越高。
- 任务范围越模糊，行动熵越高。
- skill 数量膨胀但缺少路由，选择熵越高。

## Agent 映射

| 信息论概念 | Agent 映射 |
|---|---|
| 信息源 | 文件、网页、用户消息、测试输出、日志 |
| 信道 | 工具调用、浏览器、终端、Obsidian/brainctl index |
| 噪声 | 截断、过期记忆、幻觉、格式错误、错误 OCR |
| 编码 | prompt、structured state、frontmatter、JSON schema |
| 解码 | parser、reviewer、truth gate、human reading |
| 信噪比 | evidence quality / context noise |

## 对本地大脑的要求

1. Markdown vault 是高可读信道，适合长期可审计知识。
2. SQLite/FTS 是高效检索信道，但只是派生层。
3. frontmatter 是低成本编码层，用于提高可检索性和可验证性。
4. 分类目录降低检索熵：L0 evidence、L1 atom、L2 project、L3 task、L6 review 不应混放。

## 设计启示

- 压缩不是删除信息，而是提高信噪比。
- 多模型讨论不能互相转述大段噪声；应传 evidence id、issue id、delta。
- 本地大脑的搜索结果必须能追溯来源，否则只是语义联想，不是控制输入。
