# 03 - 目的性与负反馈

## 核心概念

Rosenblueth、Wiener、Bigelow 在目的性行为研究中强调：系统可以表现出“朝向目标”的行为，而不必假定系统内部有神秘意志。目标导向可以由负反馈机制解释。

目的性行为的工程化定义：

```text
系统持续比较当前状态与目标状态，并采取行动减少差距。
```

## Agent 映射

| 目的性行为要素 | Agent 映射 |
|---|---|
| 目标 | 用户要求、验收条件、任务 contract |
| 当前状态 | repo 状态、文件内容、测试结果、brain index |
| 差距 | failing tests、missing notes、搜索未命中、用户指出缺口 |
| 行动 | 修改代码/笔记、补证据、重建索引、提交 commit |
| 证明 | test/build/search/verify 输出 |

用户指出“控制论基础似乎缺少对应理论与内容支撑”，这就是目的性控制中的误差信号：目标是“本地大脑分类有理论支撑”，当前状态是 `03-理论与元认知/控制论基础/` 为空，差距是基础理论缺失，行动就是补齐理论笔记并验证检索。

## 负反馈闭环

```text
用户目标 → 本地大脑审计 → 发现缺口 → 补齐理论 → sync/reindex/search → 回答用户
```

## 设计启示

- “用户纠正”不是失败，而是高价值反馈输入。
- Agent 应把用户指出的缺口转化为可验证 artifact。
- 完成声明必须晚于 proof-of-work，而不是早于 proof-of-work。
