# 06 - 一阶与二阶控制论

## 核心区别

一阶控制论：观察者站在系统外，研究“被观察的系统”。

二阶控制论：观察者也是系统的一部分，研究“观察系统的系统”。

对于 Hermes：

- 一阶：Hermes 审计项目、修复代码、整理本地大脑。
- 二阶：Hermes 审计自己的技能、记忆、路由、验证规则和自进化日志。

## 为什么重要

如果 Agent 只审计外部任务，却不审计自己的规则，就会出现：

- 错误 skill 被长期加载。
- 过期 memory 成为幽灵上下文。
- cron job 静默失败但无人发现。
- 多模型一致被误当事实证据。
- 自进化日志缺失却仍宣称已进化。

## Agent 映射

| 二阶控制论概念 | Hermes 实现方向 |
|---|---|
| 观察者进入系统 | Agent 记录自身工具调用、决策、失败模式 |
| 观察观察 | self-test、skill steward、evolution verifier |
| 规则可审计 | skills patch、config diff、route outcome ledger |
| 反身性风险 | prompt 自我强化、memory ghost、overfitting to recent sessions |
| 治理治理者 | private fork evolution governance、post-update healing |

## 设计启示

1. 自进化事件必须有 artifact 和 verification。
2. skill 不应只增加，也要被审计、合并、降级或删除。
3. 任何“自动优化”都需要评估它对评估器本身的影响。
4. 本地大脑的分类结构也需要日志证明，否则分类设计会退化为空目录。

## 多模型思考介入 / cybernetic multi-model intervention

- first-order cybernetics：多模型作为外部 controller 介入 object task，负责生成假设、风险和实验；最终通过 tool evidence 验证。
- second-order cybernetics：多模型与 orchestrator 共同观察 observer/controller 本身，审计 route、skill、memory、verification rule、issue ledger。

## Evidence Boundary

- 来源支持什么：该卡仅记录理论概念、经典解释或本地大脑已引用的工程化映射。
- Hermes 映射边界：Agent/多模型/技能治理映射是工程类比与设计启发，不等同于原理论在数学或社会科学意义上的严格证明。
- 不应过度推出什么：不得仅凭该理论卡宣称某项代码、流程或策略已经正确；仍需工具证据、原文证据、审计输出或运行验证。
