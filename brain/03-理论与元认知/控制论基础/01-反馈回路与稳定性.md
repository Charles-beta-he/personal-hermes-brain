# 01 - 反馈回路与稳定性

## 核心概念

控制论最小闭环：

```text
目标/参考值 r(t) → 比较器 → 误差 e(t) → 控制器 → 执行器 → 被控对象 → 输出 y(t)
                                                ↑                         ↓
                                                └──── 传感器/观测反馈 ────┘
```

误差：

```text
e(t) = r(t) - y(t)
```

控制的目标不是一次性给出“正确动作”，而是持续观测输出与目标的偏差，再根据误差调整下一步动作。

## 负反馈与正反馈

- 负反馈：输出偏离目标时，控制动作朝减少偏差的方向调整。用于稳定、纠错、收敛。
- 正反馈：输出变化会放大后续变化。用于增长、放大、级联，但缺少边界时会失控。

Agent 系统中，测试失败、用户纠正、browser console error、build error 都是负反馈输入。盲目继续生成更多代码、不断扩大 scope、未验证就宣称完成，往往是正反馈失控。

## 稳定性

稳定性关注：系统受到扰动后，是否仍能回到可接受状态。

Agent 映射：

| 控制论概念 | Hermes/Agent 映射 |
|---|---|
| 参考值 r(t) | 用户目标、验收标准、task contract |
| 输出 y(t) | 工具执行结果、代码状态、搜索结果、UI 截图 |
| 误差 e(t) | 失败测试、lint/build error、用户纠正、证据缺口 |
| 控制器 | P10/P9 规划、router、skills、多模型 judge |
| 执行器 | terminal/browser/file/cron/subagent tools |
| 传感器 | read_file/search/console/test/build/brainctl search |
| 稳定性验证 | test/build/reindex/search/verify-evolution-event |

## 设计启示

1. 每个长期任务必须显式定义目标和误差度量，否则无法闭环。
2. 每次执行后必须采样输出，否则 Agent 只是开环生成器。
3. 反馈要有延迟预算；延迟过大时会振荡，表现为反复改同一处、越修越偏。
4. 稳定系统不等于不变化；稳定系统是在扰动中保持目标一致。

## 反模式

- 只规划不验证：开环控制。
- 只看模型自评不看工具输出：传感器被替换为幻觉。
- 反馈太晚：大批量修改后才 build/test，导致误差定位困难。
- 没有 damping：遇到失败立刻大改架构，造成振荡。
