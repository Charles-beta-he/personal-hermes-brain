# 04 - 必要多样性与调节器

## 核心命题

Ashby 的必要多样性定律常被概括为：

```text
只有多样性才能吸收多样性。
```

被控系统和环境扰动越复杂，调节器就必须具备足够多的可区分状态和响应策略。否则控制器无法覆盖扰动空间。

## 形式化直觉

```text
Variety(controller) >= Variety(disturbance to be regulated)
```

这不是鼓励无限复杂，而是要求控制器的有效响应空间至少覆盖主要扰动类型。

## Agent 映射

| Ashby 概念 | Hermes 映射 |
|---|---|
| Disturbance | 用户需求变化、代码失败、上下文漂移、模型错误、工具异常 |
| Regulator | skills、router、多模型 judge、test/build gate、brainctl validate |
| Variety | 可用策略数、模型多样性、工具多样性、fallback 路径 |
| Constraint | 成本、token、时间、用户偏好、安全边界 |

多模型思考、技能路由、fallback 工具、P10/P9/P7 分层，本质上都是提升控制器多样性。但多样性必须被治理，否则技能爆炸会反过来增加选择熵。

## 设计启示

1. 多模型不是炫技，而是为复杂扰动增加调节器多样性。
2. 多 skill 不是越多越好；需要 skill graph、冷热分离、路由先验。
3. 对高风险任务，单模型单路线控制器多样性不足，应启用多模型/红队/验证门。
4. 对低风险任务，过高多样性会增加成本和延迟，应降级为简单路径。
