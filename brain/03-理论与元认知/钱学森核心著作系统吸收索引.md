# 钱学森核心著作系统吸收索引

## 0. 定位

本索引不是读书笔记，也不是把钱学森概念作为装饰性标签；它定义 Hermes 多脑如何把核心著作转成可执行能力。

吸收标准：每个概念必须落到以下至少一类 artifact：

1. brain atom：概念边界、反模式、跨脑映射。
2. workflow protocol / skill：可重复执行的流程。
3. hermes-core control plane：任务池、多模型、路由、观测、降级等机制。
4. dev engineering enablement：脚本、CLI、connector、test harness、dashboard、validator。
5. taskpool evolution task：带 capability_delta / anti_drift_check / acceptance_evidence 的演进任务。

## 4. 多脑职责矩阵

| 脑 | 著作吸收职责 | 不做什么 | 交付物 |
|---|---|---|---|
| main | 总体设计部、路由、仲裁、验收、人类介入点 | 不直接写工具，不跳过来源验证 | owner_brain/delegate_brains、decision ledger、accept/reject。 |
| research | 核心著作来源验证、概念出处、事实边界、可证伪条件 | 不直接改代码，不以二手概念替代出处 | canonical source packet、confidence、falsifier、citation map。 |
| workflow | 把概念转协议/skill/template，维护研讨厅流程 | 不替代 main 仲裁，不生成未经执行的完成证据 | meta_synthesis_protocol、handback template、skill patch。 |
| hermes-core | 运行时控制面、任务池、多模型、观测、降级 | 不吞 domain 判断，不把所有任务都变控制面 | dispatch gate、brain health、control-loop runtime、selfcheck。 |
| dev | 主脑直接开发任务；为其他脑补工程能力缺口；实现/打通/测试/交还 | 不替 research/design/media/mlops 做领域判断 | scripts/CLI/connectors/tests/browser harness/handback contract。 |
| design/media/mlops | 作为领域专家进入综合集成研讨厅 | 不因工程缺口绕过 dev 自行乱改控制面 | domain judgment + capability gap request。 |

## 5. dev 工程使能位置

dev 是“工程控制器/执行器”，不是“领域判断者”。

触发条件：

- main 直接指派开发/修复/交付任务。
- research/design/media/workflow/mlops 在原任务中遇到工程能力缺口：网页读不到、connector 缺失、API/MCP 未打通、验证 harness 缺失、数据导出不可复用、测试链路不足。

标准闭环：

```
requesting_brain -> main/route -> dev implementation -> tests/smoke -> handback contract -> requesting_brain resumes original task
```

handback 必须包含：

- delivered_artifact_path_or_command
- invocation_example
- verification_commands_and_results
- known_limits_and_failure_modes
- return_to_brain
- next_step_for_requesting_brain

## 6. P0/P1/P2 Backlog

### P0：核心吸收基线（已开始）

1. qian_core_works_registry
   - 输出：本索引 + source packet。
   - 验收：已验证书目和待验证书目分开，不把二手转述当原文。

2. meta_synthesis_atom_and_social_system_atom
   - 输出：综合集成方法论 atom、社会系统工程三层 atom。
   - 验收：每个 atom 有 capability_delta、反模式、跨脑映射。

3. dev_cross_brain_enablement_contract
   - 输出：dev brain profile、registry route、brainctl smoke。
   - 验收：能力缺口请求路由到 dev，纯领域判断仍留给专业脑/main。

### P1：协议化

1. meta_synthesis_protocol_skill
   - 输出：workflow skill/reference：综合集成研讨厅协议。
   - 验收：真实多模型讨论必须记录 source/evidence/dissent/handback。

2. qual_to_quant_task_contract
   - 输出：research -> dev 的定性到定量任务生成契约。
   - 验收：research source packet 可生成 dev 验证任务，且任务带 acceptance_evidence。

3. control_loop_spec_for_taskpool
   - 输出：taskpool 控制回路协议：desired_state / observed_state / error_signal / control_action / next_sampling / stop_or_escalate。
   - 验收：P1 evolution 任务必须能读出控制回路字段或等价证据。

### P2：运行时机制

1. global_observer_bus
   - 输出：跨脑状态观测总线。
   - 验收：brain latency/error/drift/queue health 可查询。

2. dispatch_feedforward_gate
   - 输出：dispatch 前馈风险预检。
   - 验收：高风险任务先显式分解/请求 evidence，不直接执行。

3. atom_collision_emergence
   - 输出：知识原子碰撞/涌现候选。
   - 验收：新增 atom 后产生候选建议，但不自动写入核心知识。

## 7. 验收门

Gate 0：来源与吸收矩阵
- [x] 至少三项核心来源有可追踪来源记录。
- [x] 钱学森理论不只停留在原则说明，已映射到多脑职责、dev 位置和 backlog。
- [x] 真实多模型外部建议已记录：MiMo、DeepSeek、GPT、Gemini。

Gate 1：协议可执行
- [ ] meta-synthesis protocol 可被 workflow skill 加载。
- [ ] dev handback contract 可被 taskpool 任务引用。
- [ ] research source packet 能转成 dev 验证任务。

Gate 2：控制面可观测
- [ ] brain health / observer bus 产生连续数据。
- [ ] dispatch feedforward gate 有测试覆盖。
- [ ] 任务池自检能显示控制回路状态。

Gate 3：反脆弱/扰动测试
- [ ] 注入 brain offline / model failure / source uncertainty 后，系统能降级、分解或请求人类仲裁。
- [ ] 不因多模型同意而绕过工具证据。

## 8. 反模式

- 把 dev 变成所有专业判断的替代品。
- 把“多模型同意”当成“综合集成”。
- 把钱学森概念作为口号，不落到 artifact/test/task。
- 未验证来源就写成原著结论。
- 只有 atom，没有协议、任务、验证门。
