# 综合集成研讨厅协议 v1

## 1. 触发条件

满足任一条件时启用：

- P1/P2 evolution 或 requires_multimodel 任务。
- 任务涉及核心架构、任务池、多模型、脑路由、长期知识体系。
- research 给出“高价值但不确定”结论，需要 dev 定量验证。
- 多脑/多模型对 approach / framing / implementation_order 有实质分歧。

## 2. 角色

| 角色 | Hermes 映射 | 输出 |
|---|---|---|
| 总体设计部 | main | 问题定义、约束、验收门、最终仲裁。 |
| 知识体系 | research + session/local brain | source packet、置信度、可证伪条件。 |
| 专家体系 | domain brain + 多模型 | 方案、分歧、风险、保留意见。 |
| 机器体系 | dev + hermes-core/mlops | 工程实现、测试、观测、定量结果。 |
| 沉淀体系 | workflow | protocol/skill/atom/taskpool 回写。 |

## 3. 必填输入

- problem_statement
- desired_state
- constraints_and_red_lines
- source_packet 或 evidence_gap
- participating_brains
- acceptance_evidence
- stop_or_escalate_rule

## 4. 从定性到定量闭环

1. 定性：main/research/domain brain 提出 hypothesis。
2. 来源：research 给出 evidence、confidence、falsifier。
3. 定量：dev 将 falsifier 转成脚本/测试/查询/浏览器验证/任务池 evidence。
4. 综合：多模型/多脑讨论，记录 dissent，不以多数票替代证据。
5. 仲裁：main 判断 accept / amend / split / escalate_to_human。
6. 沉淀：workflow 写入 atom/skill/protocol/task。

## 5. 研讨记录 schema

```yaml
meta_synthesis_session:
  problem: "..."
  desired_state: "..."
  source_packet:
    verified: []
    uncertain: []
    missing: []
  qualitative_hypotheses:
    - claim: "..."
      owner_brain: research
      confidence: 0.0
      falsifier: "..."
  quantitative_checks:
    - artifact: "..."
      command_or_path: "..."
      result: PASS|FAIL|WARN
  dissent:
    - participant: "..."
      objection: "..."
      resolution: accepted|rejected|split|deferred
  handback:
    requesting_brain: "..."
    implementation_brain: dev
    return_to_brain: "..."
  decision: accept|amend|split|escalate_to_human
```

## 6. 验收门

- Gate A：source/evidence 与模型意见分开记录。
- Gate B：至少一个可证伪条件转成可执行检查，除非任务被明确判定为纯概念整理。
- Gate C：dev 只交付工程 artifact，不替源脑做领域裁决。
- Gate D：分歧必须保留 dissent ledger，不能被最终摘要抹掉。
- Gate E：完成后必须指向一个沉淀位置：atom / skill / protocol / taskpool / runtime test。

## 7. 反模式

- “多模型同意”=“事实成立”。
- 没有 source packet 就直接写核心知识。
- dev 实现后自行宣布源脑任务完成。
- 没有 dissent ledger 的“综合集成”。
- 没有 handback 的跨脑工程使能。
