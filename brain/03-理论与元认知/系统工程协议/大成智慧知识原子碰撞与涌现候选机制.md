# 大成智慧知识原子碰撞与涌现候选机制 v1

## 目标

把“大成智慧”的综合涌现能力落到知识原子层，但保持 source discipline：脚本只能提出候选关系，不能自动写核心知识原子或记忆。

## 机制

1. 读取 atom markdown。
2. 提取共享概念词，形成 atom×atom 关系候选。
3. 输出候选关系、basis、source_gap、write_policy。
4. 候选进入 main/research/workflow 复核；只有通过 source_packet + falsifier + human/main acceptance 后，才能写新 atom。

## 安全红线

- 不从模型联想直接生成“事实”。
- 不自动写 `brain/04-知识原子/atoms`。
- 每条候选必须带 `source_gap`，提醒下一步核验。
- 输出定位为 suggest_only，不作为 memory。

## 参考实现

`hermes/scripts/atom_collision_emergence.py --atom-dir brain/04-知识原子/atoms --limit 12 --json`

验收要点：读取至少 5 个 atom，输出 >=2 个候选，`writes_core_atoms=false`。

## 与 dev 填充的关系

这个机制为其他脑发现“缺少工具/连接器/验证器”的组合机会，但不直接创建 dev 任务。需要创建 dev 任务时，先转成 `qual_to_quant_request`，再由 `qual_to_quant_task_contract.py` 生成 dry-run 草案。
