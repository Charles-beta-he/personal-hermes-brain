# Havel：在系统中创造裂缝

> Václav Havel, *The Power of the Powerless* (1978)
> 联系：[[03-理论与元认知/治理理论/Ostrom-公地治理8原则|Ostrom]] ｜ [[03-理论与元认知/系统理论/Prigogine-耗散结构|Prigogine]]

## 核心命题

系统的问题不是技术问题，是**默认行为模式的问题**。

在系统中生活的人都知道系统有问题，但系统的"生活方式"让他们无法改变。改变需要创造"裂缝"——在系统默认流程中嵌入制度性摩擦。

## Hermes Skills 的默认模式

```
默认模式（无摩擦）:
  发现问题 → `skill_manage('create')` → 新 skill 进入生态 → 下一个问题
  ↑ 0 成本、即时满足、不需对任何人解释

改变后模式（有摩擦）:
  发现问题 → 检查现有 skill → 有则提 PR 更新 → 没有才创建
  → 创建时自动弹出阻塞式确认：请标记一个废弃 skill
  ↑ 有成本、需思考、需承担最低限度的责任
```

## 三种制度性摩擦

### 1. 创建摩擦（Prigogine 熵债 + Ostrom 原则 5）

`skill_manage('create')` 不能立即执行，必须先回答：

```
▎ 即将在生态中创建新技能，已知：
▎   • 当前技能总数: 161
▎   • 其中无测试: 124 (77%)
▎   • 无版本记录: 122 (76%)
▎
▎ 请在创建前确认：
▎ [1] 该技能在现有库中无法找到替代 → 执行创建
▎ [2] 现有技能可以扩展覆盖 → 更新现有技能
▎ [3] 这是一个测试/实验 → 标记为 BETA 并设置过期时间
▎
▎ 根据熵债原则，创建后 48 小时内需清理等量过时内容。
```

这不是技术限制，是**哈维尔说的"裂缝"**——在系统默认流程中插入一个停顿，迫使行为从"条件反射"转为"审慎决策"。

### 2. 使用摩擦（Ashby 控制器多样性）

```
skill_view('some-skill') 返回知识卡片 + 最后评价：
▎ 技能: some-skill
▎ 健康度: C (74/100)
▎ 最后使用: 2024-03-15 (距今 402 天)
▎ ⚠️ 此技能超过 1 年未使用，标记为 DEPRECATED
```

每次加载时显示健康状态，让"使用旧技能"也有心理成本。

### 3. 废弃摩擦（Prigogine 熵债）

```
删除一个 skill 前：
▎ 该技能上次被加载时间: 2024-03-15 (402 天前)
▎ 关联引用: 3 个
▎   - ~/.hermes/skills/xxx/references/REF.md
▎   - ~/.hermes/notes/yyy.md
▎
▎ 删除后同步清理引用？[y/N]
```

## 制度性摩擦的哲学基础

哈维尔的核心洞察：

> **"系统不需要你主动支持它，系统只需要你默认为它的默认流程。系统最有力量的时候，就是你认为自己没有其他选择的时候。"**

技术系统也一样。`skill_manage('create')` 的零摩擦让创建成为默认行为。加制度性摩擦不是在"限制自由"，而是在**提供选择**——让创建者意识到自己有"不创建"的选项。
