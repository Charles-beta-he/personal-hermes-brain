# 错误分类与复盘循环

## 常见错误类型

| 类型   | 信号           | 处理                       |
| ---- | ------------ | ------------------------ |
| 观测错误 | 没读文件/没搜/没跑命令 | 补 evidence               |
| 推理错误 | 证据支持但结论跳跃    | 写 disagreement ledger    |
| 执行错误 | 改错文件/漏同步     | sync/reindex/search/test |
| 记忆错误 | WIP 进入长期记忆   | 删除/迁移到 task log          |
| 治理错误 | 规则本身导致坏结果    | 二阶审计 rule                |

## 复盘闭环

```text
失败信号 → 分类 → 根因 → 修复 → 验证 → 写入 skill/日志/本地大脑 → 后续审计
```

## Evidence Boundary

- 来源支持什么：该卡仅记录理论概念、经典解释或本地大脑已引用的工程化映射。
- Hermes 映射边界：Agent/多模型/技能治理映射是工程类比与设计启发，不等同于原理论在数学或社会科学意义上的严格证明。
- 不应过度推出什么：不得仅凭该理论卡宣称某项代码、流程或策略已经正确；仍需工具证据、原文证据、审计输出或运行验证。
