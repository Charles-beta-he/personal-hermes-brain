# 冷热分离与容量限制

> 基于 Sturgeon + Price + Dunbar 三角约束
> 联系：[[03-理论与元认知/系统理论/Sturgeon-Price-Dunbar-三角约束|三角约束]] ｜ [[06-治理与评审/技能生态/skill-steward角色定义|Steward]]

## 三层存储架构

```
┌─────────────────────────────────────────────┐
│                 活跃集 (≤ 50)                 │
│  agent 每次交互时扫描的技能列表               │
│  包括: 13 CORE + 37 ACTIVE                    │
│  替换策略: LRU（最近最少使用）                  │
├─────────────────────────────────────────────┤
│                 温存储                        │
│  DEPRECATED 技能，标记了但仍可显式加载         │
│  不自动出现在技能列表中                       │
├─────────────────────────────────────────────┤
│                 冷存储 (无上限)                │
│  ARCHIVED 技能，需显式搜索才能发现             │
│  搜索命中后自动移入活跃集                      │
└─────────────────────────────────────────────┘
```

## 容量限制

| 限制 | 值 | 依据 |
|------|----|------|
| 活跃集上限 | 50 | Dunbar 扩展 |
| CORE 上限 | 13 | Price 定律 |
| 总技能上限 | 200 | Dunbar 宽容区间 |
| 超限处理 | 阻塞新创建 | Sturgeon 定律 |

## 活跃集替换策略

```python
# LRU + 先验加权
def select_active_set(load_counts, all_skills):
    # 按使用频率排序
    sorted_by_freq = sorted(load_counts.items(), key=lambda x: -x[1])

    # CORE = top 13
    core = [s for s, _ in sorted_by_freq[:13]]

    # ACTIVE = next 37
    active = [s for s, _ in sorted_by_freq[13:50]]

    # 如果 CORE + ACTIVE < 50，从温存储补充
    if len(core) + len(active) < 50:
        # 从最近 DEPRECATED 中选最近使用的
        pass

    return core, active
```

## 给 agent 的行为约束

技能系统会在 prompt 中展示技能列表。当技能数 > 50 时：

```markdown
## Available Skills
<active_set>
  [只展示活跃集中的技能]
</active_set>

Note: There are {N} additional archived skills.
Search with session_search or search_files if needed.
```

这直接实现了 Ashby 的有效多样性降维——agent 从面对 162 个技能变成面对 ≤ 50 个。
