# 使用追踪与先验分布

> 基于 Ashby 必要多样性定律
> 联系：[[03-理论与元认知/系统理论/Ashby-必要多样性定律|Ashby]] ｜ [[06-治理与评审/技能生态/skill-steward角色定义|Steward]]

## 问题

系统多样性 R_system = 162。控制器多样性 R_controller ≈ 1~3（语义匹配）。
差距：2 个数量级。控制必然失效。

## 方案：贝叶斯先验分布

### 先验构建

```python
# 从 skill_view() 调用历史构建先验
P(load | skill_i) = count(skill_view(skill_i)) / Σ(count)

# 按频率排序：
# top-13: CORE（Price 定律 — 50% 价值）
# top-50: ACTIVE（Dunbar 扩展 — 工作集）
# rest: COLD（需显式搜索）
```

### 有效多样性降维

```
策略 1: 冷热分离
  活跃集 = top-50 skill（先验概率前 50）
  冷存储 = 剩余 112 个 skill（需搜索）

策略 2: 控制器多样性升维
  控制器 = {任务分类器 + 先验分布 + 最近使用队列}
  R_controller_effective ≈ 50

策略 3: 冗余合并
  10 个同名冲突合并后 → R_system 从 162 降到 ~150
```

## 实现：load 计数器

集成在 `skill-steward.py` 中：

```python
# 每次 skill_view() 时记录
state["load_counts"][skill_name] = state["load_counts"].get(skill_name, 0) + 1

# 每周汇总前 50
active_set = sorted(state["load_counts"].items(), key=lambda x: -x[1])[:50]

# 前 13 标记 CORE
core_set = active_set[:13]
```

## 活跃集管理

| 层级         | 容量   | 判定          | 行为          |
| ---------- | ---- | ----------- | ----------- |
| CORE       | ≤ 13 | 使用频率 top-13 | 永不淘汰        |
| ACTIVE     | ≤ 50 | 使用频率 top-50 | LRU 淘汰      |
| DEPRECATED | 无上限  | 30天未使用      | 从 ACTIVE 移除 |
| ARCHIVED   | 无上限  | 90天未使用      | 不在活跃集       |
