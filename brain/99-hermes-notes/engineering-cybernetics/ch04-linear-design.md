# 第四章 线性系统的综合与设计

## 核心观点
分析是回答"系统会做什么"，综合是回答"如何设计系统才能做想做的事"。
综合 = 反问题，比分析更难，需要明确性能指标并转化为数学约束。

## 关键概念
- **极点配置**: 通过状态反馈将闭环极点放在期望位置
- **镇定问题**: 使不稳定系统稳定（极点全部移到左半平面）
- **解耦控制**: 多输入多输出系统中消除通道间耦合
- **观测器设计**: 当状态不可测时，用输出重构状态

## 数学要点
- 状态反馈 u = Kx，闭环系统 ẋ = (A + BK)x
- 能控性判据 rank[B, AB, ..., A^(n-1)B] = n
- 能观性判据 rank[C', A'C', ..., (A')^(n-1)C'] = n
- 分离原理：控制器和观测器可独立设计

## Agent 进化映射
| 控制论概念 | Agent 映射 |
|-----------|-----------|
| 极点配置 | 调整 Agent 响应速度（快/稳权衡） |
| 能控性 | Agent 能否通过 skill/workflow 改变任意状态 |
| 能观性 | Agent 能否通过工具观察系统真实状态 |
| 观测器 | 当直接观测不可行时的推断机制（如日志分析推断错误原因） |
| 解耦控制 | 隔离不同子系统故障，防止级联失败 |
| 分离原理 | 战略层（P10）和执行层（P8）可独立优化 |

## 进化启示
**能控性 = Agent 能力的完整性**
如果 Agent 的某个状态（如"当前任务进度"）无法通过任何 workflow 改变，
说明能控性不足——需要补充 skill 或工具。

**能观性 = 可观测性基础设施**
Agent 必须能"看见"自己的运行状态：
- 用 todo 跟踪任务状态
- 用 loop-report 记录迭代历史
- 用 memory 固化长期认知

**观测器 = 自诊断能力**
当 Agent 无法直接知道某事时，需要通过推断：
- 从 build 失败日志推断代码问题
- 从截图差异推断 UI 退化
- 从用户反馈推断需求偏差

**分离原理的组织意义**
P10 设计战略（控制器）和 P9 监控执行（观测器）可以独立进化，
互不影响——只要接口（Task Prompt 格式）稳定。
