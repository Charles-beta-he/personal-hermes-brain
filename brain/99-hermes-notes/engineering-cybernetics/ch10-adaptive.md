# 第十章 自适应控制系统

## 核心观点
当系统参数未知或时变时，固定控制器失效。
自适应控制 = 在线辨识 + 实时调整，控制器随被控对象一起进化。

## 关键概念
- **模型参考自适应 (MRAC)**: 使实际输出跟踪参考模型输出
- **自校正调节器 (STR)**: 在线辨识参数 + 重新设计控制器
- **增益调度**: 根据工况切换预设控制器参数
- **鲁棒自适应**: 在扰动和未建模动态下保持稳定

## 数学要点
- MIT 规则：θ̇ = -γ·e·φ（参数按误差梯度调整）
- Lyapunov 方法设计自适应律：保证稳定性
- 持续激励条件：输入信号必须足够"丰富"才能辨识参数

## Agent 进化映射
| 控制论概念 | Agent 映射 |
|-----------|-----------|
| 未知参数 | Agent 对用户需求/项目约束的初始不确定性 |
| 模型参考 | 预设的理想工作流模板（P10 战略） |
| 在线辨识 | session 中持续学习用户偏好和项目规范 |
| 增益调度 | 根据任务类型自动切换工作模式（P10/P9/P8） |
| 持续激励 | 需要多样化的任务输入才能全面进化 |
| 鲁棒自适应 | 在新项目中保持已有能力不丢失 |

## 进化启示
**自适应 = 活的工作流**
Agent 不能是固定的 skill 集合，必须能：
1. 识别当前环境特征（项目类型、用户偏好、技术栈）
2. 调整控制策略（切换 skill 组合、调整参数）
3. 在线学习新规律（从失败和成功中提取模式）

**模型参考自适应 (MRAC)**
参考模型 = P10 定义的理想工作流
实际输出 = Agent 的真实执行轨迹
自适应律 = 根据偏差调整 skill 和 prompt

**持续激励条件**
Agent 只处理同类任务 → 参数辨识不充分 → 能力退化
必须保证任务类型的多样性：
- 前端 / 后端 / DevOps / 设计
- 新功能 / Bugfix / 重构 / 优化
- 战略规划 / 紧急响应 / 日常维护

**鲁棒自适应**
在学习新项目的同时，不遗忘旧项目的能力。
= 灾难性遗忘的对策 = 记忆系统 + 技能隔离
