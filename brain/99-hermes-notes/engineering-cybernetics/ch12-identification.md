# 第十二章 系统辨识

## 核心观点
当系统模型未知时，通过输入输出数据反推模型。
辨识 = 数据驱动的建模，是自适应控制的前提。

## 关键概念
- **黑箱辨识**: 不关心内部结构，只拟合输入输出关系
- **灰箱辨识**: 利用部分先验知识，辨识未知参数
- **最小二乘法**: 最小化预测误差平方和
- **递推最小二乘 (RLS)**: 在线更新，不用存储全部数据
- **阶次判定**: 模型复杂度与拟合精度的权衡

## 数学要点
- θ̂ = (ΦᵀΦ)⁻¹ΦᵀY（批处理最小二乘）
- θ̂ₖ = θ̂ₖ₋₁ + Lₖ(yₖ - φₖᵀθ̂ₖ₋₁)（递推形式）
- AIC / BIC 准则：惩罚过度复杂的模型

## Agent 进化映射
| 控制论概念 | Agent 映射 |
|-----------|-----------|
| 输入输出数据 | Agent 的完整 session 历史（请求→响应→反馈） |
| 黑箱辨识 | 从用户反馈中推断偏好，不假设原因 |
| 灰箱辨识 | 在已知工作流框架下，调整具体参数 |
| 最小二乘 | 拟合"什么样的 Agent 行为最让用户满意" |
| 阶次判定 | 模型复杂度 vs 过拟合（skill 数量 vs 泛化能力） |
| 遗忘因子 | 旧经验权重衰减，重视近期反馈 |

## 进化启示
**Agent 的自我建模**
Agent 应该持续进行"系统辨识"——从自身历史数据中提取规律：
1. 哪种工作流模式成功率高？
2. 用户对哪些行为最满意？
3. 什么类型的任务最容易出错？

**过拟合风险**
如果 Agent 的 skill 太多太细（高阶模型），可能在历史任务上表现好，
但泛化到新任务时失效。需要：
- AIC/BIC 准则：惩罚不必要的 skill 复杂度
- 交叉验证：在新项目/新任务上测试已有 skill
- 正则化：偏好简单、通用的 skill

**递推辨识 = 在线进化**
不用等收集大量数据后再更新，每轮 session 都微调模型参数。
RLS 公式对应 Agent：
- 新反馈到达 → 计算预测误差 → 按增益更新参数 → 遗忘旧数据

**遗忘因子**
技术栈在变，用户偏好在变，Agent 不能让旧数据永远主导。
遗忘因子 λ ∈ (0,1)：
- λ=1：永远不忘（适合核心原则）
- λ=0.95：缓慢遗忘（适合技术细节）
- λ=0.8：快速适应（适合临时项目偏好）
