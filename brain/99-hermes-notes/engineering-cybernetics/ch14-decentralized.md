# 第十四章 分散控制与递阶控制

## 核心观点
信息不完全共享时的控制策略。分散 = 各控制器只看局部信息；
递阶 = 多层控制器，上层信息粗、决策慢，下层信息细、决策快。

## 关键概念
- **信息模式**: 每个控制器能获取哪些信息
- **分散稳定性**: 仅基于局部反馈的稳定性条件
- **递阶优化**: 上层协调变量，下层局部优化
- **时间尺度分离**: 上层慢决策，下层快响应

## 数学要点
- 固定模 (Fixed Modes): 分散控制无法改变的系统极点
- 重叠分解: 子系统边界模糊时的分解方法
- Stackelberg 策略: 主从博弈，上层先动，下层跟随

## Agent 进化映射
| 控制论概念 | Agent 映射 |
|-----------|-----------|
| 信息模式 | sub-agent 能访问的上下文范围 |
| 分散稳定性 | 每个 sub-agent 独立稳定，不依赖全局信息 |
| 固定模 | Agent 的"不可变属性"（硬件限制、API 约束） |
| 时间尺度分离 | P10（季度规划）→ P9（周迭代）→ P8（日执行） |
| Stackelberg | P10 先定义战略，P9/P8 在约束下优化执行 |

## 进化启示
**信息模式决定控制品质**
sub-agent 获得的信息越少，决策越次优。但信息过多又导致：
- context 溢出
- 决策延迟
- 隐私/安全顾虑

最优信息模式：每个 agent 只获得完成任务所必需的最小信息集。

**固定模 = 接受不可改变的事实**
Agent 有固有局限：
- context window 上限
- 工具调用延迟
- 单次推理深度

不要试图"控制"这些固定模，而是在其约束下优化。

**时间尺度分离的组织意义**
- P10：季度 review，调整战略方向（慢）
- P9：周 sprint，调整任务分配（中）
- P8：日执行，调整代码实现（快）
- P7：小时级方案设计（中快）

如果 P10 每天改战略 → 系统震荡（时间尺度不匹配）
如果 P8 每季度才调整 → 响应迟钝（时间尺度不匹配）

**Stackelberg 博弈**
P10（领导者）先宣布战略，P9（跟随者）在给定战略下优化任务分配。
P10 预判 P9 的反应，选择对自身最有利的战略。
= 主从博弈 = 激励机制设计
