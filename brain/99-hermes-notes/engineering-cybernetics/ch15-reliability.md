# 第十五章 可靠性理论

## 核心观点
系统故障不可避免，但可以通过冗余、容错、维护策略使系统在故障时仍可用。
可靠性 = 在规定条件下、规定时间内完成规定功能的概率。

## 关键概念
- **可靠性函数 R(t)**: 存活到时刻 t 的概率
- **故障率 λ(t)**: 浴盆曲线（早期失效→偶然失效→耗损失效）
- **冗余设计**: 并联/表决系统提高可靠性
- **容错控制**: 故障检测 + 隔离 + 重构 (FDIR)
- **预防性维护**: 在故障前更换/修复

## 数学要点
- R(t) = exp(-∫₀ᵗ λ(τ)dτ)
- 并联系统：R = 1 - (1-R₁)(1-R₂)
- 马尔可夫可靠性模型：状态转移刻画故障与修复

## Agent 进化映射
| 控制论概念 | Agent 映射 |
|-----------|-----------|
| 可靠性 R(t) | Agent 在长时间运行中的稳定输出概率 |
| 浴盆曲线 | 新 skill（早期bug多）→ 稳定期 → 老化（技术过时） |
| 冗余 | 多个 sub-agent 独立验证同一交付物 |
| 容错 | 单个工具失败时的降级策略 |
| FDIR | 故障检测→隔离故障 skill→切换备用方案 |
| 预防维护 | 定期 code audit、skill 更新、依赖升级 |

## 进化启示
**Agent 的浴盆曲线**
1. 早期失效期：新 skill 刚上线，corner case 未覆盖 → 高错误率
   对策：严格测试、灰度发布
2. 偶然失效期：稳定运行，随机错误 → 低错误率
   对策：监控、快速恢复
3. 耗损失效期：技术栈过时、依赖废弃 → 错误率上升
   对策：定期重构、技术升级

**冗余设计在 Agent 中**
- 双审查：P8 编码 + P9 审查 + 独立 reviewer subagent
- 多方案：重要决策时 spawn 多个 agent 交叉验证
- 备份策略：主方案失败时自动切换备选

**FDIR = 自修复工作流**
Fault Detection：build/test 失败检测
Fault Isolation：git bisect / diff 分析定位问题
Fault Reconfiguration：自动 revert、切换备用方案、告警升级

**预防性维护周期**
- 每周：review 本周 session 失败模式
- 每月：audit skill 有效性和覆盖率
- 每季：技术栈评估和升级规划
