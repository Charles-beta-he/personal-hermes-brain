# 多模型评审落地方案

## 规则

- 四模型 fanout 是 provenance，不是事实证据。
- discussion `not_certified` 时，仍可采纳低风险共同建议，但必须记录 caveat。
- 事实由 orchestrator 用工具验证。
- 少数意见不能因模型便宜或名气小被丢弃；强模型也不能凭模型名自动胜出。所有 dissent 按 issue ledger、severity、evidence quality 和 experiment 处理。
- 最终交付以 post-audit、sync、reindex、search、git commit 为准。

## 本地大脑输出

- `06-治理与评审/reviews/`：记录多模型结果、分歧与 caveat。
- `05-实践与项目/tasks/`：记录执行 proof。
- `06-治理与评审/进化日志/`：记录结构演进事件。
