# 08 - 理论到影响全架构传播矩阵

## 结论

当前架构要解决的不是“某个点优化后怎么写总结”，而是把每个局部优化升级为一个可审计的控制闭环：

单点优化 → Theory Point ID 归一化 → 同理论可优化地点扫描 → Layer Impact Map → 两阶段 prepare/apply → impact smoothing → proof/selfcheck/lifecycle/evidence-spine → stable commit 或 fail-closed quarantine。

原则：局部优化不能直接升级为全局规则。只有同理论目标和影响面都被扫描、差异被平滑、验证通过后，才允许进入全架构稳定态。

## State machine

| State | Meaning | Exit gate |
|---|---|---|
| CANDIDATE_DETECTED | 单点优化被发现，尚未证明可推广 | 绑定 Theory Point ID |
| THEORY_POINT_CANONICALIZED | 理论点归一化，避免同义漂移 | 生成 Same-theory propagation targets |
| IMPACT_MAPPED | L0-L5/LX 影响面明确 | 每个 required surface 有 smoothing gate |
| PREPARE | 各受影响层准备变更，不直接 commit | 所有 required layers prepared |
| APPLYING | 执行 target-bound 优化 | 不扩大 scope，不绕过 evidence |
| VERIFYING | proof/selfcheck/lifecycle/evidence-spine/ratchet | gate 全部 PASS |
| IMPACT_SMOOTHING | 对齐层间差异，降低冲击 | health variance / diff / rollback gate OK |
| STABLE_COMMITTED | 进入稳定态 | commit + monitor |
| FAIL_CLOSED_QUARANTINE | 证据不足、影响不明、验证失败、差异过大 | 不推广为全局规则；生成 P9/P10 follow-up |

## Health / smoothing function

H_total = 0.18 EvidenceCompleteness + 0.16 TargetBoundedness + 0.16 LayerSynchrony + 0.14 VerificationPassRate + 0.12 ImpactSmoothness + 0.10 StabilityMargin + 0.08 AutonomyReadiness + 0.06 QuotaSafety。

V_bad = 0.20 EvidenceDebt + 0.18 UnsyncedLayerDebt + 0.16 VerificationDebt + 0.14 ImpactVariance + 0.12 TheoryDrift + 0.10 RecurrenceRisk + 0.06 QuotaRisk + 0.04 LifecycleDebt。

Stop rule:
- H_total 上升且 V_bad 下降：允许 stable commit。
- H_total 持平且 V_bad 持平：只允许小范围 rollout，继续 monitor。
- H_total 下降或 V_bad 上升：fail-closed quarantine。
- ImpactVariance 超阈值：进入 smoothing，不允许完成声明。

## Architecture surfaces

- L0-trace：记录 Theory Point ID、source event、evidence、health delta。
- L1-router：决定同理论优化是否升级 T1/T2/T3，防止路由漂移。
- L2-protocol：把理论点固化为 envelope/protocol/closeout 约束。
- L3-ensemble：用 cross-critique、cross-patch、issue ledger 找差异。
- L4-taskpool-brain：生成任务、proof、lifecycle、review、brain artifact。
- L5-consult-models：对高风险理论点做 target-bound discussion/ratification。
- LX-health-quota：监测 quota、model health、V(x)、rollback/quarantine 条件。
- skills：把稳定流程沉淀为 reference/skill，避免只进 memory。
- cron-gateway：保证定时/网关/消息通道不被新规则误触发或过载。

## Fail-closed 条件

任一条件满足即停止传播：

1. 没有 Theory Point ID。
2. Same-theory propagation targets 少于 2 个，且无明确 none-rationale。
3. Layer Impact Map 未覆盖 required surfaces。
4. Smoothing gate 只有口头“注意”，没有 rollback/regression/evidence/selfcheck/health/diff 之一。
5. not_certified/dissent/timeout 被提升成 certified。
6. 只改文档，不改脚本/测试/gate，但声称架构已生效。
7. selfcheck/proof/lifecycle/evidence-spine 任一失败。
8. 影响差异过大且未进入 damping。
