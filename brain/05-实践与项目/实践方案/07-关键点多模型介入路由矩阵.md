# 07 - 关键点多模型介入路由矩阵

## 结论

不是所有关键点都应该触发四模型。长期策略是：主层级保持稳定，先落地语义/控制面 overlay，用路由矩阵决定哪些关键点进入 T0/T1/T2/T3 多模型思考。

主层级不一步到位改名/重排；介入点先通过 project、playbook、atom、review、task log、derived index 呈现。只有当 overlay 被验证持续优于现有层级，才进入可逆迁移。

## 为什么不改现有 Obsidian 主层级

1. Obsidian 主层级是 human navigation contract。它服务长期可读性、手动浏览、引用路径、MOC 链接和历史语义。
2. 当前结构已经有直接 MOC/index，结构审计为 0 缺口。没有证据说明重排会提升检索或决策质量。
3. 大规模改目录会破坏 wikilink、历史任务日志、sync mirror、brainctl index、外部脚本路径和人类肌肉记忆。
4. 多模型介入是一层 controller/routing logic，不是必然的 ontology replacement。
5. 一步到位会把“认知架构实验”变成“不可逆信息迁移”。这违反 evidence-first 和 rollback gate。

## 长期是否应该一步到位

当前答案：不应该现在一步到位。

长期答案：可以有条件迁移，但必须先满足迁移门槛。

### 迁移门槛

| Gate | Requirement | Evidence |
|---|---|---|
| G1 | overlay 至少运行 4 周 | review/task/evolution logs |
| G2 | 检索命中率或决策质量显著提升 | before/after query benchmark |
| G3 | 无 broken wikilinks / 无 ghost task | structural audit |
| G4 | 目录映射可逆 | migration map + rollback script |
| G5 | 双写期稳定 | old path + new semantic path both searchable |
| G6 | P10/P9 ratification | not_certified caveat resolved or accepted risk |
| G7 | 用户显式批准 | no implicit destructive reorganization |

## 推荐路线

| Phase | Action | Directory impact | Stop gate |
|---|---|---|---|
| P0 | 路由矩阵 overlay | 不改主层级 | search + selfcheck PASS |
| P1 | 派生索引/标签/alias | 不改主层级 | bilingual queries top-hit |
| P2 | 影子层级 shadow MOC | 新增，不移动旧文件 | old/new links both valid |
| P3 | 小样本迁移实验 | 复制样本 | rollback verified |
| P4 | 批量迁移候选 | 仍需显式批准 | benchmark wins + no broken links |
