# Semantic overlay before hierarchy rewrite

## Principle

Do not rewrite the Obsidian main hierarchy in one step when a semantic/control-plane overlay can deliver the same routing benefits with lower blast radius。

## Why

Main hierarchy is a human navigation contract。It anchors MOCs, wikilinks, historical logs, sync mirrors, scripts, and user muscle memory。A new theory layer should first be represented as project/playbook/atom/review/routing matrix, not as a destructive directory migration。

## Migration rule

A hierarchy rewrite requires:

- measured benefit over current hierarchy；
- reversible migration map；
- dual-write/shadow-MOC period；
- no broken wikilinks；
- explicit user approval；
- P10/P9 ratification or accepted-risk record。
