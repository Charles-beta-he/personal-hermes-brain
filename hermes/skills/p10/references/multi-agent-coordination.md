# Multi-Agent Coordination — 复杂项目拆分与并行执行

> T16: 支持 5+ 并行 sub-agent 无冲突完成

## 拆分原则

```
MECE 原则:
  - Mutually Exclusive: 子任务不重叠
  - Collectively Exhaustive: 子任务覆盖全部需求

接口优先:
  - 先定义模块间接口，再并行开发
  - 接口一旦确定，不轻易变更

数据隔离:
  - 每个 sub-agent 工作在自己的目录/分支
  - 最终由 P9 合并，解决冲突
```

## 协调协议

### 阶段 1: 接口定义（串行，P10/P9）

```
1. P10 定义战略 + 模块边界
2. P9 设计模块间接口契约
3. 所有 sub-agent 确认接口（阻塞点）
```

### 阶段 2: 并行开发（并行，P8 agents）

```
4. 按 dependency_graph 启动 sub-agents
5. 无依赖的模块并行开发
6. 有依赖的模块等待前置完成
```

### 阶段 3: 集成验证（串行，P9）

```
7. 收集所有子模块输出
8. 执行集成测试
9. 解决接口不匹配问题
10. 输出最终交付物
```

## 冲突预防

```
文件级冲突:
  - 每个 sub-agent 修改不同的文件
  - 如必须修改同一文件 → 拆分为更细粒度的子任务

逻辑级冲突:
  - 接口契约明确定义行为
  - 单元测试覆盖接口契约

依赖级冲突:
  - dependency_graph 严格 DAG
  - 禁止循环依赖
```

## 失败处理

```
单个 sub-agent 失败:
  - 不影响其他 agent（隔离）
  - 记录失败原因
  - 尝试 fallback skill 或重新分配

多个 sub-agent 失败:
  - 暂停整个项目
  - P10 重新评估拆分策略
  - 可能是接口设计问题或任务粒度过大
```

## 规模限制

```
当前限制:
  - 最大并行度: 3 个 sub-agents（受 context budget 限制）
  - 最大任务数: 10 个 chunks
  - 最大项目复杂度: 5 个模块

扩展路径:
  - 增加 context budget → 提升并行度
  - 优化 skill 置信度 → 减少验证轮次
  - 引入工作流编排 → 自动化依赖管理
```
