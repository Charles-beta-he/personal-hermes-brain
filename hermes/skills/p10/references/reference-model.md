# Reference Model — 理想工作流定义

> ch10 自适应控制: 参考模型 = 理想工作流，实际执行与之比较产生偏差

## 标准任务闭环（参考模型）

```
[0] 需求澄清
    └── requirement-clarification skill
    └── 输出: AC + 性能指标权重 + 验收标准
    └── 选择最优控制模式（紧急/常规/探索）

[1] 战略设计 (P10)
    └── 读取 reference-model.md
    └── 检查 V(t-1)，如 V̇ < 0 触发战略调整
    └── 检查 Context Budget（如 <30% 建议拆分）
    └── 输出: p10-strategy.md

[2] 任务拆解 (P9)
    └── 分解为 ≤7 个原子任务（cognitive-load 约束）
    └── 定义每个子任务的信息模式
    └── 按 skill 置信度排序选择执行 skill
    └── 输出: p9-tasks.md + todo list

[3] 编码实现 (P8/P7)
    └── 按 TDD 执行
    └── 自适应采样验证（关键路径高频/常规低频）
    └── 偏差检测: 实际 vs 参考模型
    └── 记录 OODA 各阶段耗时

[4] 代码审查
    └── 独立 reviewer（冗余设计）
    └── 安全扫描 + 基线测试
    └── 如置信度 < 0.5 的 skill 被使用 → 额外审查

[5] 验证测试
    └── UIMax audit + browser harness
    └── 计算本轮 V 贡献值
    └── 极限环检测（同问题复发检查）

[6] 构建部署
    └── semantic-release 自动版本
    └── FDIR: 构建失败 → 自动定位并 revert

[7] 上线验证
    └── 生产环境健康检查
    └── 计算 V(t)，更新 V̇
    └── 用户反馈捕获（强化学习 reward）

[8] 事故/复盘
    └── FDIR: 检测→隔离→恢复→复盘
    └── 如 V̇ < -0.05，触发根因分析
    └── 遗忘因子 λ 调节（临时上下文衰减）

[9] 持续优化
    └── loop 执行，每轮计算 V
    └── skill 评分更新（贝叶斯 + 卡尔曼）
    └── session 健康度自动记录
    └── 4H 自扫描监控
```

## 偏差定义

| 偏差类型 | 检测方式 | 阈值 | 响应 |
|---------|---------|------|------|
| 跳过阶段 | 检查是否缺失 [0]-[9] 任一 | 任何缺失 | 警告并补回 |
| 验证缺失 | 检查每轮后是否有验证结果 | 连续 2 轮无验证 | 强制验证 |
| 超时 | 记录每个阶段耗时 | > 参考模型 200% | 告警，建议分解 |
| 质量下降 | UIMax 评分 | < A | 阻断，要求修复 |
| 极限环 | 同问题重复出现 | 3 次 | 切换策略维度 |

## 更新规则

reference-model.md 每季度由 P10 review 更新一次。
更新条件:
- V̇ < -0.05 连续 2 次
- 新类型任务首次出现且现有模型不适用
- 用户重大反馈要求流程调整
