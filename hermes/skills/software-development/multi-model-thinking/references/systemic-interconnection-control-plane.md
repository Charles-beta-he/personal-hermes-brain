# Systemic interconnection theory → semantic control-plane pattern

Use when the user asks for systemic “互相关联不足”, theory/core works, long-term maintainable project governance, or balanced multi-direction improvement across profile/taskpool/dispatch/proof/ratification/learning.

## Core diagnosis

Do not frame the issue as simply “no links” when skeleton artifacts already exist. The common failure is: rich policy atoms exist, but no executable semantic control-plane contract binds task classification → dispatch route → worker handoff → evidence labels → proof gate → ratification authority → learning/writeback.

## Theory families and core works

1. Cybernetics / systems theory
- Wiener, *Cybernetics*
- Ashby, *An Introduction to Cybernetics*
- Conant & Ashby, “Every Good Regulator of a System Must Be a Model of That System”
- Beer, *Brain of the Firm*, *The Heart of Enterprise*
- Forrester, *Industrial Dynamics*
- Meadows, *Thinking in Systems*, “Leverage Points”

Mapping: project profile must become the regulator’s executable model, not prose context.

2. Software architecture / modularity
- Parnas, “On the Criteria To Be Used in Decomposing Systems into Modules”
- Brooks, *The Mythical Man-Month*, “No Silver Bullet”
- Baldwin & Clark, *Design Rules*
- Bass/Clements/Kazman, *Software Architecture in Practice*
- Evans, *Domain-Driven Design*
- Fowler, *Refactoring*, *Patterns of Enterprise Application Architecture*
- Ousterhout, *A Philosophy of Software Design*

Mapping: separate stable invariant kernel from project-specific overlay.

3. Socio-technical systems / organization design
- Conway, “How Do Committees Invent?”
- Trist/Emery socio-technical systems work
- Senge, *The Fifth Discipline*
- Skelton & Pais, *Team Topologies*
- Argyris & Schön, *Organizational Learning II*

Mapping: worker handoff must be a typed envelope with owner boundaries, not free prompt context.

4. Safety / evidence engineering
- Deming, PDCA / *Out of the Crisis*
- Popper, *The Logic of Scientific Discovery*
- Reason, *Human Error* / Swiss cheese model
- Leveson, *Engineering a Safer World* / STAMP-STPA
- Toyota Production System / Jidoka; Liker, *The Toyota Way*

Mapping: use layered evidence gates, not a single generic token proof gate.

5. Knowledge management / learning organizations
- Schön, *The Reflective Practitioner*
- Nonaka & Takeuchi, *The Knowledge-Creating Company*
- Wenger, *Communities of Practice*
- Argyris & Schön, double-loop learning

Mapping: distinguish single-loop evidence logging from double-loop profile/skill/runtime policy updates.

6. Complex adaptive systems / flexible governance
- Simon, *The Sciences of the Artificial*
- Holland, *Adaptation in Natural and Artificial Systems*
- Ostrom, *Governing the Commons*
- Taleb, *Antifragile*

Mapping: use risk-tiered routing and small-batch evolution; do not force every task through the heaviest gate.

7. Language / semantic commitment
- Wittgenstein, *Philosophical Investigations*
- Brandom, *Making It Explicit*
- Evans, ubiquitous language

Mapping: classifications such as `fullstack-integrated` are commitments that imply required inspections, evidence, blockers, and ratification levels.

## Recommended output structure

1. State whether the problem is absent links vs skeleton links lacking semantic linkage.
2. Provide theory map: theory → core work → key claim → concrete control-plane mechanism.
3. Propose stable kernel:
   - task taxonomy
   - evidence kinds and required labels
   - typed worker handoff envelope
   - risk-tiered ratification semantics
   - learning/writeback policy
   - rollback/review/expiry signals
4. Propose project overlay:
   - domain map
   - source precedence
   - release policy
   - local acceptance topology
   - private evidence policy
5. Propose implementation slices:
   - advisory schema / Workpad landing
   - read-only selfcheck WARN
   - classification dry-run
   - typed handoff contract
   - profile-aware proof WARN gate
   - risk-tiered ratification
6. Include maintenance rules:
   - no direct fail-closed runtime change from weak consensus
   - require impact map, rollback boundary, and soft-launch period
   - prune stale/dead rules
   - do not convert one-off failures into global rules without repeated evidence or user correction

## Multi-model evidence posture

For this class of task, 4-model fanout is useful for breadth, but planner fanout or weak consensus is advisory only. Unless `discussion_result.json` and target-bound 4/4 ratification pass, land outputs as strategy/profile guidance, not runtime enforcement certification.

## Anti-patterns

- Copying all profile fields into prompt context and calling that “integration”.
- Adding more policy prose without runtime consumer mapping.
- Treating Workpad as status dump instead of feedback/control dashboard.
- Making every task T3/fullstack by default; this breaks flexibility and cost balance.
- Upgrading not_certified/weak_consensus into a fail-closed rule.
